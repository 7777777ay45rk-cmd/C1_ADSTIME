# WHY this Allow comes before the blanket "?" disallow below: assets/css/style.css and
# assets/js/main.js are served with a cache-busting "?v=<timestamp>" query string (see
# includes/config.php's adstime_asset_url()), so browsers always fetch a fresh copy right after
# a deploy instead of an old cached one. Google's renderer needs to actually fetch these to
# render pages properly for ranking purposes - blocking that would make Google see broken,
# unstyled pages, which hurts SEO far more than any junk-URL crawl budget waste would. A more
# specific Allow rule beats a broader Disallow rule in robots.txt, so this keeps exactly that
# one pattern crawlable while the rule below blocks every other "?" URL.
Allow: /*?v=*

# SEO-NOTE: every crawlable page on this site already has a canonical tag pointing at its clean,
# query-string-free URL (see includes/header.php), and nothing here serves different indexable
# content based on a query string - so there's no reason for Google to ever crawl or index a
# "?"-suffixed variant of a page. This one rule replaces what used to be a growing list of
# specific junk patterns (?list=, _bdsid=, _bd_prev_page=...) and covers whatever bots invent
# next too, instead of adding a new line here every time Search Console shows another one.
# WHY this doesn't affect real ad campaigns: robots.txt only controls search-engine crawling,
# not what a real visitor's browser can load - a Google or Meta ad linking to a page with
# ?utm_source=... or ?gclid=... still works exactly the same for every person who clicks it, and
# GA4/conversion tracking reads those parameters client-side regardless of this file. This rule
# only stops Googlebot from separately crawling and indexing that parameterized copy of a page,
# which the canonical tag was already telling it to skip anyway.
Disallow: /*?
